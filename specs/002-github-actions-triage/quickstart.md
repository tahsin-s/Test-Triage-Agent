# Quickstart: GitHub Actions QA Triage

This guide is intentionally slice-based. Each slice produces a CLI-visible or GitHub-visible result so the work can be reviewed incrementally without waiting for the whole system to be complete.

## Prerequisites

- A GitHub repository with Actions enabled.
- The project checked out locally with the existing repo scripts and Playwright suite.
- `gh` installed if you want to trigger GitHub workflow calls from the terminal.
- Optional: a personal access token or repository secret for private artifacts.

## Slice 1: Validate the repo contract and local CLI behavior

Goal: confirm the repo still produces deterministic tag and report outputs before wiring GitHub Actions.

Run:

```bash
cd /home/tahsins/git/Test-Triage-Agent
./.venv/bin/python src/qe_agent/tagging/extract_tags.py
./.venv/bin/python src/qe_agent/reporting/prepare_playwright_output.py \
  --report-dir ./banking-platform-voltio.QA/playwright/playwright-report \
  --output ./artifacts/ai-report.json
```

Expected outcome:
- The tag extractor prints the discovered BDD tags.
- The report-prep step writes a compact summary JSON to `artifacts/ai-report.json`.

This is the first human-verifiable proof point: the repo can still read the branch data deterministically.

## Slice 2: Validate the tag recommendation flow locally

Goal: ensure a bounded plan can be generated before we send it remotely.

Run:

```bash
cd /home/tahsins/git/Test-Triage-Agent
./.venv/bin/python src/qe_agent/tag_recommender.py \
  --report artifacts/ai-report.json \
  --descriptions src/qe_agent/tagging/tag_descriptions.json \
  --max-tags 3 \
  --output /tmp/tag_plan.json
```

Expected outcome:
- A JSON tag plan is created at `/tmp/tag_plan.json`.
- It contains an ordered list of tags and runtime estimates.

This proves the execution order logic works before the GitHub Actions integration is introduced.

## Slice 3: Validate the remote branch lifecycle in GitHub

Goal: confirm the repository is ready for branch-level workflow execution.

Manual steps in GitHub web UI:
1. Open the repository.
2. Go to Settings > Actions > General.
3. Ensure Actions are enabled.
4. Confirm workflow permissions allow reads and the necessary artifact access.
5. If private artifact access is needed, add the required secret under Settings > Secrets and variables > Actions.

Expected outcome:
- GitHub Actions is enabled for the repo and the workflow can run on the target branch.

This is the minimum required manual setup before the automation can be exercised.

## Slice 4: Build and validate the remote workflow contract

Goal: define the GitHub Actions workflow and test it on a branch with a known tag list.

Create or update workflow files under `.github/workflows/` and include:
- a `workflow_dispatch` trigger
- an input schema for `tags`, `max_tags`, and `branch`
- a step to fetch the deterministic tag catalog and previous report
- a step to run Playwright with only the selected tags
- a final artifact upload step

Run locally to validate the same contract with the repo scripts:

```bash
cd /home/tahsins/git/Test-Triage-Agent
node scripts/orchestrate-tag-runner.js \
  --tag-plan /tmp/tag_plan.json \
  --project-dir ./banking-platform-voltio.QA/playwright \
  --dry-run
```

Expected outcome:
- The orchestrator prints the selected tag sequence without executing the full suite.
- This is a safe dry run of the GitHub Actions execution plan.

## Slice 5: Trigger the remote workflow from the CLI or GitHub UI

Goal: prove the selected tags can be dispatched to GitHub Actions.

Using `gh` CLI:

```bash
gh workflow run triage-playwright.yml \
  --ref main \
  -f branch=main \
  -f tags='@smoke,@auth,@goals' \
  -f max_tags=3
```

Expected outcome:
- A workflow run appears in GitHub Actions.
- The run executes only the selected tags in the provided order.

In the GitHub UI, check:
- Actions > workflow run > logs
- Artifact summary generated by the workflow

## Slice 6: End-to-end verification

Goal: verify the full developer-to-Copilot-to-GitHub flow completes as a single bounded triage cycle.

Validation criteria:
- Copilot reads tag inventory and prior report.
- Unknown tags are described and resolved.
- Tag order is generated and bounded.
- The workflow receives the tag plan.
- Only the selected tags are run.
- A compact summary artifact is produced.

This is the exit condition for the feature: not “the whole repo is autonomous,” but “the branch is triaged in a bounded, reviewable flow.”
